# 🦴 TMJ-Diagnosis 仕様書: 両側顎関節ベクター編集 UI 拡張

## 1. プロジェクト・機能概要

| 項目 | 詳細 |
| :--- | :--- |
| **プロジェクト名** | **TMJ-Diagnosis** |
| **機能の目的** | 左右の顎関節画像を同時に参照しながら、下顎頭と関節窩のアウトラインを少数点の開いたポリラインとして編集・確定できるデュアルウィンドウ UI を構築する。 |
| **前提** | F-1/F-3 実装済（画像読み込み・Wasｍ連携・単一ビュー編集）。Rust Wasm モジュールでベクター化処理を行う基盤があること。 |
| **備考** | 顎関節は左右に存在するため、UI/データ構造とも左右を独立して扱えること。 |

***

## 2. 参考データ

| 種別 | パス | 用途 |
| :--- | :--- | :--- |
| サンプル画像（左） | `./sample/left_condyle.jpg` | 左側顎関節の検証用 |
| サンプル画像（右） | `./sample/right_contyle.jpg` | 右側顎関節の検証用 |

※ 右側ファイル名は提供どおり（`right_contyle.jpg`）。Wasm 側で左右判別・処理時にはメタデータの付与で識別する。

## 3. 機能要件 (F: Functional Requirement)

### F-5: 左右同時編集ビュー

| 番号 | 要件 | 詳細 | 担当技術 |
| :--- | :--- | :--- | :--- |
| **F-5.1** | デュアルウィンドウ構成 | **左用**・**右用** 2 つの編集キャンバスを横並びで表示し、それぞれ独立したズーム・パン・ベクター編集が可能であること。 | Next.js (TS) / Konva |
| **F-5.2** | 左右別画像ロード | 1 つ目のファイル選択で左用、2 つ目で右用を読み込める UI を用意し、サンプル画像で初期状態を検証できるようにする。 | Next.js (TS) |
| **F-5.3** | Wasm 連携 | Wasm 関数に対し、左右それぞれのグレースケール画像とメタ情報（`side: "left" | "right"`）を渡し、処理結果を受け取る。 | Next.js (TS) & Rust Wasm |
| **F-5.4** | ベクター表示 | Wasm から返却されたベクターを、左右それぞれのキャンバスに描画する。下顎頭(`condyle`)、関節窩(`fossa`)を色分けし、開いたポリライン（始端・終端が異なる）として扱う。 | Konva |
| **F-5.5** | 最終確定 | 左右別々に「アウトライン確定」操作ができ、確定した座標は JSON として保持・確認できる。 | Next.js (TS) |

### F-6: ベクター編集操作

| 番号 | 要件 | 詳細 | 担当技術 |
| :--- | :--- | :--- | :--- |
| **F-6.1** | アンカーポイント制限 | 各アウトラインのアンカーポイント数は **最大 10 点** 程度（推奨値）。Wasm 側で初期点数を抑制し、UI からも制限を超えないよう制御する。 | Rust Wasm / Next.js |
| **F-6.2** | ポリライン構造 | ポイント列は閉じない開曲線とし、開始・終了点を重複させない。JSON フォーマットもポリライン前提とする。 | Rust Wasm |
| **F-6.3** | 操作モード定義 | 画像パン・ズームとアンカー編集の操作が衝突しないよう、以下の操作体系を統一する。<br/>- **パン**: キャンバス上で `Space + 左ドラッグ`<br/>- **ズーム**: `Ctrl + ホイール`（センターに対してズーム）<br/>- **アンカードラッグ**: 通常の左ドラッグ（Space/Ctrl 非押下）<br/>- **アンカー追加**: `Shift + 左クリック`（補間位置に追加）<br/>- **アンカー削除**: アンカー選択後 `Delete` または `Backspace` | Konva / Next.js |
| **F-6.4** | 編集フィードバック | 選択中のアンカーポイントを視覚的に強調し、操作ガイドを UI に表示する（ショートカット一覧など）。 | Next.js (TS) |

> **実装メモ（F-6.3）**  
> React の `useEffect` で `window` に `keydown` / `keyup` リスナーを追加し、`Space` キーの押下状態を `useState` で管理する。その状態に応じて Konva の `<Stage>` の `draggable` プロパティを動的に切り替える。

### F-7: プロジェクト状態表示

| 番号 | 要件 | 詳細 | 担当技術 |
| :--- | :--- | :--- | :--- |
| **F-7.1** | 処理ログ | 左右それぞれの処理ステータス（未処理・処理中・完了・エラー）を表示できるステータスパネルを設ける。 | Next.js (TS) |
| **F-7.2** | サンプルロード導線 | サンプル画像をワンクリックで読み込めるショートカットを提供し、検証が容易なようにする。 | Next.js (TS) |

## 4. コーディング要件 (Rust Wasm 拡張)

### R-5: 両側対応セグメンテーション

* **API**: `process_image_for_tmj` を拡張し、引数に `side: &str` を追加する、または `process_image_for_tmj_side(data, width, height, side)` のような新関数を提供する。
* **出力 JSON**: 左右共通の形式で返却する。例:

```json
{
  "side": "left",
  "condyle": [[x0, y0], [x1, y1], ...],
  "fossa": [[x0, y0], [x1, y1], ...]
}
```

* **ポイント数制御**: `condyle` / `fossa` それぞれ約 10 点前後にサンプリングしたポリラインを返却する（輪郭抽出後に単純化アルゴリズムを適用）。
* **アルゴリズム留意点**:
    * 下顎頭・関節窩は楕円ではなく曲線となるため、輪郭追跡後に曲線の始点・終点を左右端で選択するなどの工夫を行う。
    * 輪郭の単純化（ポイント数制御）には、Rustの **`rdp` クレート** を利用して Ramer–Douglas–Peucker アルゴリズムを適用し、アンカーポイント数を約 10 点に削減することを推奨する。

***

## 5. フロントエンド構成指針

1. **コンポーネント構造**: 現在の `VectorStage` を左右対応に拡張し、親コンポーネントで左右の状態を管理する。状態は `left` / `right` キーを持つオブジェクトで統一。
2. **ショートカットガイド**: 操作説明を明示した小パネル（またはツールチップ）を用意し、ユーザーが混乱しないようにする。
3. **状態管理**: 左右ごとに
    * 画像情報
    * ベクター編集状態
    * 確定済みデータ
    * 処理ステータス
   を保持する。
4. **JSON 表示**: 確定した左右のアウトラインを統合して表示・コピーしやすい UI を提供する。

***

## 6. テスト観点

* サンプル画像（左右）を読み込んだ際に自動的に 10 点前後のポリラインが生成されるか。
* 左右それぞれで独立にズーム・パン・アンカー編集ができるか。
* 操作ショートカットが干渉せず動作するか（Space/Ctrl/Shift/Del）。
* 確定した JSON が左右それぞれオープンパスの座標列として保存されるか。
* 片側のみ処理済みの場合でも UI が破綻しないか。

***

この仕様に基づき、両側顎関節の同時編集に耐えうるプロトタイプを構築してください。GUI 操作体系を明文化し、ユーザーが直感的に両側のアウトラインを調整できる状態が目標です。***
